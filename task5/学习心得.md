# Task5 学习心得（ch07 · Skills）

> 这一章我最开始是"照着教程能跑通，但一换配置就猜"，学完后的变化是：能对着一个 `skills/` 目录，
> 不运行就说出"这一轮会花多少 token、改哪一行不会生效"。下面是具体学到的东西和踩掉的坑。

## 我学到了什么

### 1. "渐进式披露"其实只有第一级是框架做的

框架（`SkillsMiddleware`）只做两件事：**扫一层目录**、**只解析 frontmatter 里的 `name` 和 `description`**。
然后每次模型调用前，把这两个字段拼进 system prompt。那 42 行正文，框架从头到尾没有读——
不是压缩、不是摘要，是压根没用。

### 2. 正文是模型自己 `read_file` 读进来的

正文落地为 `messages` 里的一条 `ToolMessage`。这个位置决定了两个连锁结论：

- 它过不了委派边界：委派时 `messages` 被整个重置，所以父 Agent 精读过的 SKILL.md，子 Agent 一个字都看不到，得自己再读一遍；
- 它读一次之后就一直留在 `messages` 里，之后每一轮模型调用都在为它付费。

### 3. 索引是"每轮租金"，不是"一次性押金"

索引成本 ≈ Σ(name + description + path) × 模型调用次数。所以 `description` 写 800 字不是文档问题，是账单问题。
规范里 1024 字符的上限，超了是**截断后照用**、不报错。

### 4. 索引是会话快照

`before_agent` 看到 state 里已经有 `skills_metadata` 就直接返回（**连空列表也算"已有"**）。
所以同一 thread 里改 SKILL.md 不生效，必须换 `thread_id` 才重扫。

### 5. 子 Agent 的技能是"各自装配"，不是继承

GP 的"自动继承"其实是 `graph.py:761` 把同一份 `skills` 列表**字面复制**过去；
自定义子 Agent 必须自己写 `skills` 字段，而且判的是**真值**（空列表 = 没有）。
更有意思的是：同一个参数，主 Agent 用 `is not None` 判空，子 Agent 用真值判空——两种规则不一致。

## 我解决了哪些问题

### 1. 怎么不花额度就验证"提示词里有什么"

造了一个**录制型假模型**：继承 `FakeMessagesListChatModel`，在 `_generate` 里把收到的 messages 抄一份再返回固定答案。
零 token 就断言出"索引进提示词、正文不在"。这一招以后看任何中间件都通用。

### 2. YAML 冒号让技能"静默消失"

第一版 `SKILL.md` 的 `description: BASE VERSION: 用于…` 因为多出来的 `: ` 导致 frontmatter 解析失败，
整份技能被跳过，框架只打一行 warning。改成用 JSON 字符串字面量包 `description` 解决。
这不是脚本 bug 的噪音，而是真实项目里技能"莫名少一个"的典型原因。

### 3. 429 限流

真实模型实验被网关限流（429）。给模型套了录制壳 + 指数退避重试，脚本自己能扛过限流。

### 4. 思维导图文字重叠

叶子折成两行时，旧布局按"叶子数"分配高度，长叶子会压到下一个分支。改成按"行数"算高度后不再重叠。

### 5. 纠正了自己的一个错误模型（最值钱的一条）

我一开始以为"技能文件被整体读进提示词"，导致预测题和测验大面积答错。
后来用**四个抽屉**（system prompt / state / messages / 文件）重建了心智模型：
正文一直在文件里，提示词里只有名字和描述，正文只有模型自己读的时候才进对话。
这个纠正比任何新知识点都重要——它让我从"背结论"变成了"能推出结论"。
